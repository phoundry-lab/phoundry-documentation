## Usage tips

- Use `oninput` for real-time feedback (e.g. live search) and `onchange` for commit-on-blur behavior.
- Set `type="search"` with an icon for a native-feeling search field that shows a clear button in some browsers.
- Pair with `FormField` to get labels, descriptions, and error messaging for free.
- Use `variant="trueGhost"` for inline editing where the parent already supplies hover/focus treatment. It has no border, fill, or focus ring — provide your own affordance if the field stands alone.

## Width and styling

`fullWidth` defaults to `false` for plain, clearable, and affixed inputs. Set it when the field should fill its container:

```svelte
<TextInput fullWidth placeholder="Your name" />
<TextInput fullWidth icon={PhiIcons.search} clearable placeholder="Search..." />
```

The stable root hook is `.ph-text-input`. `class` and `style` apply to this shell in every configuration; `element`, native attributes, events, and attachments target the inner input. Do not depend on the internal DOM or part classes.

The root always exposes `data-size`, `data-variant`, and `data-full-width`; boolean states use exact values such as `[data-full-width='true']`. Disabled and read-only state remain native input attributes.

Sizes consume the published `--ph-comp-h-sm`, `--ph-comp-h-md`, and `--ph-comp-h-lg` tokens and corresponding `--ph-comp-icon-*` tokens from `phoundry-ui/styles/components.css`. Color values come from the applied named Theme. Local `--_ph-*` properties are implementation details. Scoped, unlayered styles may take precedence over utility classes; use `fullWidth` for full-width layout and root inline styles for custom dimensions.

When upgrading, replace `size="xs"` with `size="sm"` and add `fullWidth` wherever the previous automatic full width was required. `sm` now uses the shared 1.5rem height (previously 1.375rem). Replace `.text-input` root selectors with `.ph-text-input`. Styles that previously targeted a plain input now target the shell; keep input bindings and native attributes on the component as before. Focus uses the same variant chrome as hover, without a blue or accent-colored focus ring. This includes the clear button. `trueGhost` stays chrome-free.

The shared `.ph-text-field` primitive in `phoundry-ui/styles/components.css` keeps variant chrome and size configuration aligned with NumberInput. All three fields use `--ph-field-radius` (0.5rem) and `--ph-input-shadow` for outline surfaces. Focus and hover share the same appearance; native blue focus rings are suppressed.

`outline` has a quiet translucent background, muted border, and input shadow. `fill` uses the stronger neutral control background with no visible border or shadow; the distinction remains on hover and focus.
