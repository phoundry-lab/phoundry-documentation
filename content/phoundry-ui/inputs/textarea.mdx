## Usage tips

- Use `resize="auto"` for comment boxes or chat inputs where height should match content.
- Set `resize="none"` when the textarea lives inside a fixed-height layout (e.g. a split pane).
- Pair with `FormField` to add a label, helper text, and character count.
- The auto-resize mode recalculates on every input - for very long documents, prefer `resize="vertical"`.
- Use `variant="trueGhost"` for inline editing where the parent already supplies hover/focus treatment. It has no border, fill, or focus ring — provide your own affordance if the field stands alone.

## Styling

`.ph-textarea` is the stable root identification hook. Variant chrome and size configuration use the shared `.ph-text-field` primitive; anatomy stays in scoped CSS; `data-size` always identifies the selected size. `class`, `style`, native attributes, attachments, and `bind:element` target the textarea. `data-variant` exposes `outline`, `fill`, `ghost`, or `trueGhost`; `data-resize` exposes `none`, `vertical`, or `auto`. The outline surface shadow uses `--ph-input-shadow`. Focus uses the same variant chrome as hover, without a blue or accent-colored focus ring. `trueGhost` stays chrome-free. The theming guide documents public theme parts; other part selectors and `--_ph-*` properties remain implementation details.

The shared `.ph-text-field` primitive in `phoundry-ui/styles/components.css` keeps variant chrome and size configuration aligned with NumberInput. All three fields use `--ph-field-radius` (0.5rem) and `--ph-input-shadow` for outline surfaces. Focus and hover share the same appearance; native blue focus rings are suppressed.

`outline` has a quiet translucent background, muted border, and input shadow. `fill` uses the stronger neutral control background with no visible border or shadow; the distinction remains on hover and focus.
