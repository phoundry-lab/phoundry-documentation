## Usage tips

- Call `setupOverlays()` once in your root layout to initialize all overlay managers together, including the modal stack and `ModalOverlay`.
- Use `useModalManagerAPI()` inside components (context-based) or `getModalManager()` from non-component code (global singleton).
- `manager.open(Component, props, options)` returns a `Promise` that resolves when the modal closes, with the value passed to `onClose(result)`.
- Modals stack - opening a second modal layers it on top. `manager.closeAll()` dismisses the entire stack.

## Mobile keyboard

Set `mobile` once on the overlay in your root layout to keep every modal in the
visible viewport when the on-screen keyboard opens:

```svelte
<ModalOverlay mobile={isMobileClient} />
```

`mobile` defaults to `false`. Enable it from the application's native platform
identity. The overlay follows visual viewport resize and scroll events, recenters
the entire modal stack above the keyboard, and leaves pinch zoom to the browser.
The library `Modal` panel also limits its height to the available space. Custom
dialogs should use a scrollable body for long content.

## CSS styling

`.ph-modal` is the stable identification hook for Modal. Part selectors and `--_ph-*` properties are internal. Component CSS is scoped and unlayered; Consumer classes remain additive and utility overrides may lose precedence.

The content panel uses `.ph-modal-panel`. AlertDialog, ConfirmDialog, and PromptDialog use `.ph-alert-dialog`, `.ph-confirm-dialog`, and `.ph-prompt-dialog`. Named panel sizes are `sm` 25rem, `md` 35rem, `lg` 45rem, `xl` 60rem, and `full` the window width minus 2rem. Without a named size, `width` accepts a CSS inline size and defaults to 24rem. Class strings are no longer accepted for width or iconColor. All built-in dialogs and manager options accept CSS colors for iconColor, such as `var(--ph-accent)`. `--ph-modal-panel-height` caps panel height; the existing `--phi-modal-panel-height` alias is still accepted.

Keep the shared component stylesheet and a named Theme imported. Decorative motion respects reduced-motion preferences.

For custom modal content, apply the shared `.ph-dialog-panel` visual surface explicitly. The former `.modal-panel` class remains a compatibility alias.
