## Usage tips

- Omit children for icon-only buttons and supply `aria-label` or `title` for the accessible name.
- Use `tooltipPlacement` to anchor the automatic tooltip to the button; the default placement is `top`.
- Set `noTooltip` to use the native browser title attribute instead of the phoundry-ui tooltip system.
- The `link` variant removes height and padding - it renders inline like a text link.
- `ButtonGroup` supports text and icon segments inside an inset, rounded shell.

## Link and loading semantics

A linked Button prevents activation while `disabled` or `loading`, and exposes `aria-disabled`. Button toggle semantics (`aria-pressed`) apply to native buttons. Loading-only buttons infer icon-only geometry. When `target="_blank"` is supplied without an explicit `rel`, Button supplies `noopener noreferrer`; explicit `rel` values are preserved.

## CSS customization

The stable root is `.ph-btn`. Variant and size use `data-variant` and `data-size`;
icon-only layout is derived from an icon or spinner and the absence of children.
`iconOnly` has been removed. Width uses `fullWidth` or Consumer CSS. Shared
`--ph-comp-h-*`, `--ph-comp-icon-*`, `--ph-btn-radius`, `--ph-button-shadow`,
`--ph-button-specular`, `--ph-button-shading`, and `--ph-text-shadow` properties
provide supported customization. Internal part selectors and `--_ph-*` values
are implementation details.

Keyboard focus uses the hover treatment without a default ring. Persistent `active` state uses the item-selection foreground/background hooks; native pressed state uses the variant's pressed treatment. `.ph-btn-label` and `.ph-btn-icon` are supported theme parts alongside `.ph-btn`. Use `:root .ph-btn` for an ordinary CSS root override with matching scoped-style specificity, or documented public custom properties.
